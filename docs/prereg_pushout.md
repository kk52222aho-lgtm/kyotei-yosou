# 前向き記録 事前登録 — 押し出し検出器(上位1%)

**2026-09-03 作成。1件目を記録する前に書いた。以降いかなる条項も変更せん。**

## 0. これは勝ちやない

過去データで出とるんは検出の数字だけや。**回収は一度も壁を超えてへん。**
合格の宣言は本記録の通過後にのみ行う。

## 1. 何を検出しとるか

1号艇が **1コースを奪われる**(進入コース > 1)レース。歴史では全体の 1.02% しか起きんが、
起きたら1号艇の勝率が 55.19% → 11.75% に落ちる。

検出器は `data/pushout_model.joblib`(2026-09-03 凍結):

| | |
|---|---|
| 特徴 | `grab_max` `grab_sum` `press_max` `press` `b1_out` `b1_hold` `v_out` の7本 |
| 出どころ | 全部 `results_st`(Kファイルから掘った進入コース151万行)の**そのレースより前**の履歴 |
| 風速・波高 | **使わん**。Kファイル=レース後の値やから。抜いても AUC 0.8518→0.8505 |
| 学習 | 20220106–20260902、248,950レース |
| 閾値 | **p ≥ 0.106749**(上位1%)。**動かさん** |
| 再学習 | **せん** |
| SHA256 | `41d4ddec5aa3867d6e3a790963c7e385bf4a520b6c33d10ee6db1b00c45ab019` |

**朝の出走表だけで発火する。**直前情報も展示も要らん。

## 2. 記録の手順

- 毎日、開催全レースにスコアを付ける。**発火したレースだけやのうて全レースを記録する**
  (後から閾値を動かして解釈せんため。判定は必ず凍結閾値でやる)
- 発火 = `p >= 0.106749`。歴史では **1日あたり約1.5レース**
- 記録は締切前。**着順・払戻は一切見ずに保存する**
- 後日 `settle` で確定払戻を突合する

## 3. 何と比べるか

記録には必ず**予測が要らん手**を同時に入れる:

| | 手 |
|---|---|
| A | **1号艇を素直に買う**(そのレースで。予測不要) |
| B | 全レースで1号艇を買う(発火に関係なく) |
| C | 2/3/4号艇の単勝 |

**判定は「発火レースで A が沈むか」と「C が壁を超えるか」の2つ。別々に扱う。**

## 4. 決着可能性 — 数字を見る前に書く

**これが一番大事や。** [[principle-dumb-baseline]] の隣に置く条項。

発火は年約550本。そこから逆算すると:

| 測るもん | 年550本でのSE | 決着するか |
|---|---|---|
| **押し出し率**(歴史22.1%) | ±1.8pt | **する。1年で十分** |
| **1号艇勝率**(歴史30.3% vs 全体54.7%) | ±2.0pt | **する。半年で十分** |
| **単勝ROI**(歴史93.8%) | **±14pt** | **せん** |

**単勝の回収率は、この記録では決着せん。**
歴史 n=1,989 で CI が [80.3%, 109.6%] やった。年550本ならもっと開く。
CI下限を**損益分岐(100%)**の上へ出すには、点推定で **113%** が要る。
**真値が100%あっても届かん設計や。**

→ **最有力の結末は「検出は前向きでも生きとる。回収は未確定。」**
これを先に書いとかんと、後から「惜しい」「N足す」が必ず出る。

## 4bis. 🚨 訂正(2026-09-08。**基準を厳しくする方向の訂正**)

**作成時に「単勝の払戻率85%」と書いたんは誤りやった。**正しくは **75%**(控除25%)や。
根拠3つが一致した: ①リポジトリ自身が `analyze.py`/`backtest_trifecta.py`/`FINDINGS.md` で
「控除率~25%」と書いとる ②確定オッズの 1/オッズ 総和の中央値 1.3598 → 払戻率の下界 **73.5%**
③他3競技(地方競馬80/78.8%・ばんえい80/79.1%・オートレース70/68.7%)は公称と実測が一致し、
**ズレとったんは競艇だけ**。

さらに「壁」いう語で**2つの別の閾値を混ぜとった**:
- **払戻率(75%)** = 無作為に賭けた時の回収。超えたら「選別に腕がある」だけ
- **100%** = 損益分岐。**ここを超えて初めて金になる**

→ 出口3の合格条件を **85% → 100%** に訂正した。**条件は厳しくなる。**
  訂正時点で N=3 で、1件も判定に使うてへん。4節のMDE計算は元から100%基準やったので変わらん。

## 5. 出口は3通り

1. **押し出し率が 15% を割る、または 1号艇勝率が 45% を超える**
   → 検出器は前向きで死んだ。**閉じる。再解釈せん**
2. **押し出し率 ≥ 15% かつ 1号艇勝率 ≤ 40%(N=300で判定)**
   → 検出は本物。**やが回収は未確定のまま。**張らん。次はオッズの記録を貯める
3. **上に加えて 単勝ROIのCI下限が100%(損益分岐)を超えた**
   → 合格。ただし4節のとおり**この記録では起きん見込み**や。起きたら疑ってかかる

## 6. オッズ

発火レースは `odds_probe` の記録対象と突合できる。**締切前オッズは別途貯まる。**
「濃いレースの中でオッズが割に合う瞬間だけ拾う」は歴史オッズが無いので前向きにしか測れん。
本記録はその材料を作る工程でもある。**ただし本事前登録の判定にオッズは使わん。**

## 7. 判定の時期

**N=300 に達した時点。**年550本なので約7ヶ月。早開けせん。
N が足りん間に中間集計を見るのは構わんが、**条項の基準は動かさん**。
